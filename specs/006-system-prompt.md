# 006 — System prompt module (verbatim)

## [SPEC]

- **Objective**: Encode Build Spec §10's system prompt verbatim into one exported constant, plus the one addition the Build Spec itself calls for ("When wiring the prompt, also instruct the model to return its final answer in the `ModelReport` structure from section 5") — the single source the harness (spec 008) imports rather than inlining prompt text.
- **Inputs/Outputs**: The exact text of Build Spec §10, copied character-for-character — no paraphrase, no "improvement," no reformatting of the WORKFLOW/PRIORITY/OUTPUT/CONSTRAINTS AND ESCALATION sections. TRD §3.4 explicitly defers to the Build Spec as the one authoritative verbatim copy and instructs specs not to restate it a second time to avoid drift — this spec is the single code-level copy; Build Spec §10 remains the single prose-level copy, and this spec's content must be checked against it, not re-derived from memory.
- **Design Pattern**: none — simple case (one string constant, one export).
- **Bounded-AI boundary**: Entirely deterministic from the human's perspective of this spec: the prompt *text* is authored by humans (the Build Spec's owners), not generated by an LLM at build time. The model reads this prompt at runtime and generates a report from it — that generation is out of this spec's boundary (spec 008's harness invokes it).
- **Verification Oracle**: A unit test (`tests/unit/prompt.test.ts`) that diffs the exported `SYSTEM_PROMPT` constant's text against a frozen copy of Build Spec §10's prompt block (stored as a second file or inline fixture) and asserts byte-for-byte equality — any future accidental edit to the prompt (by a human or an agent) fails this test immediately, which is the point: "changes need both owners' agreement" (Build Spec §10) is enforced as a diff-check, not merely a comment.
- **Intellectual Control**: A dedicated test-against-frozen-copy is what makes "verbatim" a checked fact instead of a claim — without it, a well-meaning later edit (e.g., "cleaning up" a typo) could silently drift the prompt in a way that changes model behavior without anyone noticing it wasn't supposed to be touched.
- **Constraints**: No dependency. This file contains no logic beyond string export and the one appended instruction about returning `ModelReport`-shaped output — that addition is placed clearly separated (e.g., appended after the verbatim block, not interleaved into it) so the verbatim boundary stays visually unambiguous for the next person reading the diff.
- **Edge Cases**: None beyond "did the text match exactly" — this is as close to a pure constant as this codebase gets. If the Build Spec's prompt text itself ever changes (out of this spec's authority — Build Spec §10 says changes need both owners' agreement), this spec's frozen-copy fixture must be updated in the same change, never left stale while the live constant diverges.
- **UI States**: N/A — no UI files.
